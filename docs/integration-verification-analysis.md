# 브라우저 통합 검증 분석

orchestrator: Codex

사용자 승인: 기존 화면의 실제 실행 검증과 핵심·실패·입력 경계 테스트를 확대한다. 실제 Neon DB와 개인 데이터는 접근하지 않는다. 저장소 규칙, README, 기존 33개 테스트와 화면 API 구조를 확인했다. 초기 Git 작업 트리는 깨끗하다.

범위: production 빌드 화면을 로컬 테스트 서버에서 실행하고 9개 메뉴, 빈 데이터, 저장 실패, 정상 저장 후 재조회와 중복 요청을 확인한다. 실제 API handler는 기존 mock SQL 테스트로 별도 검증한다.
가정: 시험 응답/메모리 저장은 테스트 하네스에만 존재하며 운영 API에 fixture 분기를 추가하지 않는다. 모든 /api 요청을 하네스가 처리하고 DATABASE_URL은 로컬 접근 불가 주소로 덮어써 외부 연결을 차단한다.
질문/답변: 승인된 실행 검증 범위이므로 추가 확인 없이 진행한다. UX 재설계가 아닌 기존 동작 검증과 최소 오류 수정이므로 3종 시안 게이트는 적용 대상이 아니다. 기존 Neon 구조를 유지하며 Supabase 전환은 하지 않는다.
완료 기준: 실제 브라우저 관찰, 실패 시 입력 보존과 재시도, 저장 재조회, 테스트/빌드의 실제 종료 결과 기록.

재현된 문제: Growth 저장 응답을 3초 지연시킨 상태에서 저장 버튼 dblclick 1회가 POST 2회를 전송했다(하네스 mutations 1→3). 저장 중 재진입 ref와 버튼 disabled 상태를 추가하고 finally에서 해제한다. 성공할 때만 입력 초기화/모달 닫기를 유지한다.
